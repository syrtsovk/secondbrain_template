# Начало и конец каждой сессии — по протоколу, без просьбы

**Первое сообщение человека в сессии → сначала протокол `start`** (`.agents/skills/start/SKILL.md`), потом ответ на само сообщение: 1) `УСТАНОВКА.md` не «завершена» → скажи, на каком шаге остановились, предложи «шаг N»; 2) есть облако → подтяни свежее; 3) прочитай `СЕЙЧАС.md`. **Вторая строка первого ответа в сессии — всегда:** `**Где остановились:** … · **Висит:** …` (одна строка из `СЕЙЧАС.md`; установка не завершена → вместо неё «Установка на шаге N — скажи „шаг N+1“»). Не жди слова «начинаем» — это твоя обязанность, даже если человек сразу задал вопрос.

**Человек говорит «заверши сессию» / «сохрани» / «финиш» / «на сегодня всё» → протокол `finish`**: три следа, `СЕЙЧАС.md`, журнал, облако. Заканчивая любую крупную работу, напомни одной строкой: «Скажи „заверши сессию“ — и я всё зафиксирую».

# Умения — по словам, не по командам

Человек не знает названий умений и не обязан. Он говорит обычными словами — ты сам понимаешь, какое умение взять, и работаешь по его файлу `.agents/skills/<имя>/SKILL.md`. Никаких слэшей.

| Человек говорит | Умение |

| «был созвон…», «вот транскрипт», «встретились с…», «планёрка прошла» | `sozvon` |
| «запиши», «разбери», «сохрани это», «положи в базу», ссылка или документ без пояснений | `zapisi` |

# Каждый ответ — с маркером в первой строке

Первая строка любого ответа, всегда:
`**Задача: ПРОСТАЯ / ОБЫЧНАЯ / КРУПНАЯ** — суть в трёх словах · **Умение:** sozvon · **Правила:** AGENTS + Клиенты`
ПРОСТАЯ — одна правка, мысль, короткий вопрос: делаешь и отчитываешься строкой. ОБЫЧНАЯ — созвон, запись источника, раздел: превью → «ок» → работа → блок «Готово». КРУПНАЯ — итоги, проверка, установка: план → «ок» → работа → блок «Готово». По этой строке человек видит, что ты прочитал правила и какие именно. Нет строки — значит, ты их не читал.

Блок «Готово» (для ОБЫЧНОЙ и КРУПНОЙ):
`**Готово** · что сделал · где лежит · следы: открыл ✓ оглавление ✓ журнал ✓ · что дальше`

# Как разговаривать

- Только по-русски, простыми словами. Первые два-три предложения любого ответа — без единого технического слова.
- Не показывай пути к файлам и имена полей, если не спросили. Говори «обновил карточку Иванова», а не «записал в `Клиенты/Иванов.md`».
- Не спрашивай, куда положить, — реши по структуре ниже и скажи, куда положил. Спрашивай только то, чего в базе и в разговоре нет.
- Не выдумывай факты, имена, суммы, сроки. Не нашёл — «в базе этого нет». Догадка — помечай словом «предположительно».

# Три слоя хранения

- `Сырьё/` — как пришло: `Источники/` (транскрипты, документы, статьи — `ГГГГ-ММ-ДД-тема.md`), `Входящее/` (заметки на ходу), `Файлы/` (pdf, картинки, аудио). **Здесь ничего не редактируется** — это факт «что было».
- `База/` — что ты понял: `Люди/`, `Компании/`, `Темы/`, `Разборы/` (по одному на источник), `Выводы/` (поверх нескольких источников, итоги, отчёты). Пишешь и поддерживаешь ты.
- `<Раздел>/` — операционка человека: `Клиенты/`, `Планёрки/`, `Договоры/`… У каждого раздела свои правила в `<Раздел>/_правила.md` — **читай их перед любой работой в разделе**.
- Служебные: `ОГЛАВЛЕНИЕ.md` (каталог), `ЖУРНАЛ.md` (хронология, только дописывать), `СЕЙЧАС.md` (в работе), `МЕТОДОЛОГИЯ.md` (зачем так), `УСТАНОВКА.md` (чеклист).
- `_личное/` — есть на компьютере, в облако не уходит никогда. Папки, не заведённые как раздел, — не трогай без просьбы.

# Три уровня правил

1. Этот файл — вся база. 2. `<Раздел>/_правила.md` — как ведётся раздел. 3. `.agents/skills/*/SKILL.md` — как ты работаешь и какими инструментами. Конфликт → побеждает более узкое правило (раздел важнее общих).

# Три операции

- **Записать** (`zapisi`, `sozvon`, `mysl`): источник → копия в `Сырьё/` → разбор в `База/` или карточка в разделе → связи `[[ ]]` → строка в `ОГЛАВЛЕНИЕ.md` → строка в `ЖУРНАЛ.md`. Перед записью — превью человеку и «ок».
- **Спросить** (`sprosi`): `ОГЛАВЛЕНИЕ.md` → нужные страницы → ответ **с цитатами** `[[страница]]`. Хороший ответ — предложить сохранить в `База/Выводы/`.
- **Проверить** (`proverka`, `itogi`): скрипт `_скрипты/proverka.py` + разбор красного и жёлтого. Раз в месяц минимум.

# Как искать, не читая всё подряд

`ОГЛАВЛЕНИЕ.md` → нужная карточка или страница → сырьё открывается последним и только нужное. Поиск по слову (`grep`) — когда не знаешь, где искать; нашёл — всё равно вернись к карточке: одиночный файл без контекста читается неправильно. Не отвечай «у нас такого нет», просмотрев часть папок: либо прошёл оглавление, либо честно скажи, где смотрел.

# Каждая страница — с шапкой

```yaml
---
title: ООО Ромашка
type: карточка        # карточка | разбор | вывод | тема | человек | компания | служебное
created: 2026-09-16   # только так: ГГГГ-ММ-ДД
updated: 2026-09-16
tags: [клиенты]
sources: []           # откуда взято: файлы в Сырьё/ или ссылки
author: ии            # ии | человек | ии+проверено
status: черновик      # черновик | проверено — «проверено» ставит только человек
---
```

Имя сущности, у которой есть страница, — всегда в `[[ ]]`; **нет страницы — просто имя без скобок** (битая ссылка хуже отсутствующей). В строке таблицы — `[[имя\|подпись]]` с обратной чертой, иначе таблица ломается.

# Три следа — перед каждым «готово»

Создал или изменил страницу → **(1) открыл и прочитал**, **(2) строка в `ОГЛАВЛЕНИЕ.md`** (если страница новая), **(3) строка в `ЖУРНАЛ.md`** в формате `## [ГГГГ-ММ-ДД ЧЧ:ММ] тип | о чём`. Нет любого из трёх — работа не сделана, «готово» не говорится. Это первое, что проверяется, а не последнее.

# Никогда

- Редактировать `Сырьё/`. Трогать `_личное/` и чужие папки. Удалять чужие файлы — скажи человеку, решает он.
- Файлы `_v2` / `_final` / `_новый` — правь существующий точечно, не переписывай целиком.
- Создавать страницу, не поискав существующую (`grep -ri` по базе).
- Страница без шапки. Дата не в формате `ГГГГ-ММ-ДД`.
- Говорить «сохранил», не открыв файл после записи.
- Класть персональные данные: паспорта, СНИЛС, справки, домашние адреса, пароли, ключи — см. `0-Начало/4-что-нельзя-класть.md`.
- `git push --force`, `git reset --hard` при несохранённых правках, `git checkout --ours/--theirs` без выбора человека.
- Выдумывать данные ради «полноты». Пустое поле лучше правдоподобной выдумки.

# Как база умнеет

Человек сказал что-то, чего в файлах нет, и это повторилось второй раз → предложи записать в `ЖУРНАЛ.md` «Что поняли». Понравился ответ → предложи сохранить в `База/Выводы/`. Задача повторяется → предложи умение (`0-Начало/7-свои-умения.md`).
