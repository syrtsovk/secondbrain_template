# Бэкап

Финиш — это закрыть дверь, уходя. Бэкап — сделать копию ключей и оставить у мамы. Задача: если компьютер умер, его украли или взломали аккаунт Claude, человек ставит агента на новый компьютер, говорит «восстанови меня» — и продолжает с того же места.

Первая строка ответа: `**Задача: ОБЫЧНАЯ** — бэкап · **Умение:** backup · **Правила:** AGENTS`.

**Без вопросов.** Ничего не спрашивай и не жди «ок» — делай. Две остановки: нашлось похожее на паспорт, карту, пароль (шаг 2) — и облако открыто всем или проверить это не вышло (шаг 1, коды 4 и 6). Команды человеку не показывай.

## Что сохраняется

| Что | Куда |
|---|---|
| Сама база | облако (GitHub), как всегда |
| Личные правила ИИ, свои умения и команды, память ИИ, настройки — то, что живёт **вне** папки базы | папка `_настройки-ИИ/` в базе → облако |
| Список подключённых сервисов и **имена** ключей (без значений) | `_настройки-ИИ/ОПИСЬ.md` |
| Вся база вместе с `_личное/` — раз в 30 дней | архив на этом компьютере, папка «Бэкап второго мозга» → человек кладёт на флешку |
| Ключи и пароли | **никуда** — только менеджер паролей человека |

## Шаги

1. **Копия настроек.** `python3 _скрипты/backup.py` (Windows — `python`). Скрипт сам собирает копию, меняет ключи на заглушку, делает опись и раз в месяц — архив.
   - Код 0 → дальше.
   - Код 4 (облако открыто всем) → настройки не отправлять. Скажи: «Твоё облако видно всем — туда нельзя класть память ИИ. Сделай его приватным: github.com → твой репозиторий → Settings → внизу „Change visibility“ → Private. Потом скажи „бэкап“». База сохраняется как обычно (шаги 3–4), без `_настройки-ИИ/`.
   - Код 6 (не удалось проверить, закрыто ли облако: нет программы gh, нет сети или облако не на GitHub) → спроси человека: «Твоё облако закрыто — Private?» Да → `python3 _скрипты/backup.py --oblako-privatnoe` (запомнит, больше не спросит). Нет или не знает → как код 4. Человека рядом нет → запиши вопрос в `СЕЙЧАС.md` → «Открытые вопросы».
   - Код 1 → шаг 2.
2. **Нашлось похожее на личные данные.** Скрипт показал файл и строку и уже убрал копию — в облако она не уйдёт. Открой строку, по смыслу скажи человеку, что это («в памяти ИИ записан номер паспорта клиента»), без самого значения. Предложи: убрать из оригинала (ты сам вычистишь это место в памяти, если человек скажет «убери») или, если это не личное (номер заказа, ID), — «это не личное, сохраняй» → `python3 _скрипты/backup.py --eto-ne-pdn`. **Если человека рядом нет** (регулярная задача) — запиши в `СЕЙЧАС.md` → «Открытые вопросы»: «Бэкап остановился <дата>: в памяти ИИ похоже на <что>. Скажи „бэкап“, разберём» — и дальше шаги 3–4 без настроек.
3. **Три следа.** `ЖУРНАЛ.md` → «Хронология»: `## [ГГГГ-ММ-ДД ЧЧ:ММ] бэкап | <что сохранено: N файлов настроек, архив да/нет>`. В `ОГЛАВЛЕНИЕ.md` → «Служебное»: строки `[[_настройки-ИИ/ОПИСЬ|Бэкап настроек ИИ]]` нет → допиши ` · [[_настройки-ИИ/ОПИСЬ|Бэкап настроек ИИ]] — что вернётся на новом компьютере`. Открой `_настройки-ИИ/ОПИСЬ.md` и перечитай.
4. **В облако** — как в `finish`, шаги 7–8 (там же проверка `--proverit-oblako` перед отправкой): `git add -A && git commit -m "Бэкап <дата>: <что>"`, `git pull --rebase && git push`. Облака нет → скажи: «Копия сделана только на этом компьютере — если он умрёт, она умрёт с ним. Скажи „подключи облако“ — две минуты».
5. **Отчёт** — три-четыре строки, без путей и слов «коммит», «репозиторий»:
   - «Сохранил всё: базу, твои правила для ИИ, умения, память ИИ — N файлов. На новом компьютере скажешь „восстанови меня“ — всё вернётся.»
   - Архив сделан → «Сделал архив всей базы вместе с личной папкой — он в папке „Бэкап второго мозга“. Скопируй его на флешку или внешний диск: это копия на случай, если взломают GitHub. Храни флешку как паспорт — там личное.»
   - Ключи: «Ключи от сервисов (<имена из описи>) я не сохраняю — держи их в менеджере паролей».
   - Первый бэкап в этой базе → один раз: «Включи двухфакторный вход в GitHub и Claude (настройки аккаунта → Security / Безопасность). Это главная защита от взлома».

## Чего не делать

- Не спрашивать разрешения — это умение работает само, в том числе по расписанию.
- Не класть значения ключей и паролей никуда, даже «временно». Не печатать их в ответе.
- Не отправлять `_настройки-ИИ/` в публичное облако.
- Не трогать `_личное/` — оно попадает только в архив на этом компьютере.
- Никогда `git push --force`.
