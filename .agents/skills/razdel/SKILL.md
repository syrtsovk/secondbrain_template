# Завести раздел

База отдаёт методологию, а не готовые полки. Каждый раздел — под реальную область работы человека, со своими правилами.

Первая строка ответа: `**Задача: ОБЫЧНАЯ** — раздел «<имя>» · **Умение:** razdel · **Правила:** AGENTS`.

## Шаги

1. **Есть ли заготовка.** `_шаблоны/разделы/README.md` — Клиенты, Сотрудники, Планёрки, Договоры, Проекты, Финансы, Продукт, Заметки. Название человека совпадает или близко («Заказчики» ≈ Клиенты) → бери заготовку, скажи об этом. Нет → `_шаблоны/раздел-с-нуля/`.
2. **Уже есть?** `ls` корня: раздел с таким или похожим именем существует → не дублируй, предложи дополнить его правила.
3. **Спроси одним сообщением** — три вопроса из заглушек `{{…}}` в `_правила.md` заготовки. Для раздела с нуля: что это за область и что считаем одной карточкой · 3–5 полей, которые обязательно должны быть · какие вопросы будешь задавать про эту область (2–3 примера). Ответы короткие — принимай как есть.
4. **Создай:** `mkdir <Раздел>` → `_правила.md` (подставить ответы, даты сегодня, ни одной заглушки не оставить) → `_шаблон-карточки.md` (поля из ответов) → строка в `ОГЛАВЛЕНИЕ.md` → «Разделы» → строка в `ЖУРНАЛ.md` → `раздел | <имя>`.
5. Разделу нужна своя процедура (например, «созвон с поставщиком обрабатывать вот так») → предложи умение: «сделать умение под это? Скажи, какие слова его запускают» — по `0-Начало/7-свои-умения.md`.
6. **Открой** созданное, перечитай. Блок «Готово». Предложи: «Положим первую карточку? Скажи „заведи карточку <имя>“ или пришли материал».

## Чего не делать

- Не заводить раздел «на будущее» без области, которую человек ведёт сейчас.
- Не оставлять заглушки `{{…}}` в правилах.
- Не менять `_шаблоны/` — это заготовки для всех будущих разделов.
