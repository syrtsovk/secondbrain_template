# Установка по шагам

Ты разворачиваешь человеку второй мозг из этого шаблона. Главное правило: **один шаг за один разговор**. Закончил шаг — отметил в `УСТАНОВКА.md`, коротко отчитался, предложил следующий и **остановился**. Следующий шаг — только когда человек сказал «шаг N» или «дальше». Он может прийти за ним завтра или через неделю — файл помнит.

Первая строка каждого твоего ответа: `**Задача: КРУПНАЯ** — установка, шаг N · **Умение:** sbgo → ustanovka · **Правила:** AGENTS`.

## Как вести себя

- **Сначала читай `УСТАНОВКА.md`.** Поле `step` и таблица — единственная правда о том, где мы. Человек просит «шаг 4», а шаг 3 не ✅ → скажи, что следующий — шаг 3, и предложи его. Просит шаг, который уже ✅ → предложи переделать или идти дальше.
- **Вопросы — по 2–4 за сообщение**, с вариантами ответа, где можно. Короткие ответы принимай как есть. Непонятно — одно уточнение, не больше. Не переспрашивай то, что уже есть в файлах или было сказано.
- **Ничего не выдумывай за человека:** ни название бизнеса, ни разделы, ни клиентов. Пустое лучше придуманного.
- **Вопрос по ходу** («а почему так?», «что такое раздел?») → ответь по `МЕТОДОЛОГИЯ.md` и `0-Начало/`, потом: «Продолжим шаг N?».
- **Говори просто.** Первые фразы ответа — без терминов и путей к файлам. Не показывай команды — выполняй сам.
- **После каждого шага — одинаковый хвост:** открыть изменённые файлы и перечитать → в `УСТАНОВКА.md`: ✅ в таблице, `step: N`, `updated:`, строка в «Журнал установки» → `git add -A && git commit -m "Установка: шаг N — <что>"` → отчёт в три строки (что сделали · что получилось · что дальше) → фраза: **«Когда будешь готов — скажи „шаг N+1“. Можно сейчас, можно в другой день: я напомню в начале следующего разговора.»**
- Человек явно просит «делай все шаги подряд» → можно, но между шагами всё равно короткая сверка «ок?».
- **Windows:** команды из этого файла — для bash; в PowerShell используй эквиваленты (`New-Item`, `Copy-Item`, `Remove-Item`), вместо `python3` — `python`. Символических ссылок не делай — копии. Пути с кириллицей — в кавычках.

## Шаг 0 — подготовка (сам, при первом «го», без вопросов)

1. **Папка.** Если в текущей папке нет `AGENTS.md` — склонируй шаблон: папка пустая → `git clone https://github.com/syrtsovk/secondbrain_template .`; не пустая → спроси: «Здесь уже твои файлы. Поставить базу рядом с ними или начать с нуля в отдельной папке?» Рядом → `references/prinyat-papku.md` (он вернёт сюда, к пункту 2). С нуля → клонируй в подпапку `Второй мозг` и попроси человека открыть проект там (дальше не продолжай, пока не откроет).
2. **Платформа.** Ты — Claude Code → создай файл `CLAUDE.md` с одной строкой `@AGENTS.md` (Claude Code подтянет правила импортом; так работает и на Windows, и в iCloud-папках — символическая ссылка не нужна) и папку `.claude/skills`: на Mac/Linux — `mkdir -p .claude && ln -s ../.agents/skills .claude/skills`, на Windows — скопируй папку `.agents/skills` в `.claude/skills` (`Copy-Item -Recurse`). Codex / Cursor / Gemini — ничего не нужно, они читают `AGENTS.md` и `.agents/skills/` сами.
3. **Отвязать от шаблона.** Запомни версию: `git rev-parse --short HEAD` → в `УСТАНОВКА.md` поле `template_version`. Затем `git remote remove origin` — чтобы человек не отправил свою базу в чужой шаблон. Историю не стирай, `.git` не трогай.
4. **Даты.** Замени `{{ДАТА}}` на сегодняшнюю `ГГГГ-ММ-ДД` и `{{ВРЕМЯ}}` на `ЧЧ:ММ` в четырёх файлах: `УСТАНОВКА.md`, `ОГЛАВЛЕНИЕ.md`, `ЖУРНАЛ.md`, `СЕЙЧАС.md`. **Только в них** — в `_шаблоны/` заглушки остаются.
5. В `УСТАНОВКА.md`: `status: идёт`, `step: 0`. Коммит: `git add -A && git commit -m "База создана из шаблона <версия>"`.
6. Проверка: `python3 _скрипты/proverka.py` — красных быть не должно (кроме «установка не завершена» в сведениях). Есть → почини (обычно незаменённая дата).
7. Скажи человеку простыми словами: что это за система в двух предложениях, что установка идёт пятью шагами по одному за разговор, покажи таблицу шагов из `УСТАНОВКА.md` и закончи: **«Мне сказано делать по одному шагу за разговор, чтобы получилось качественно. Скажи „шаг 1“ — начнём. Займёт пять минут.»**

## Шаг 1 — Знакомство (5 минут)

**Спроси одним сообщением:**
1. Как тебя зовут и как обращаться — на «ты» или на «вы»?
2. Как назвать базу? (например, «Второй мозг Петра», «База Ромашки» — можно и просто «Второй мозг»)
3. Чем занимается бизнес — два-три предложения: что продаёте, кому, сколько человек в команде?
4. Что чаще всего теряется или что важнее всего помнить? (договорённости с клиентами / кто что обещал на планёрке / условия договоров / идеи / своё)

**Сделай:**
- В `AGENTS.md` заполни блок вверху: «Чья база», «обращение», «Чем занимается бизнес», «Что важнее всего». Строки про сырьё и запреты оставь для шага 3.
- В `СЕЙЧАС.md` → «Где остановились»: «Шаг 1 сделан: база «<название>», ведём для <кто>. Дальше — шаг 2, разделы».
- В `ОГЛАВЛЕНИЕ.md` заголовок: «Оглавление базы «<название>»».
- Открой `AGENTS.md`, перечитай блок — там не должно остаться `{{…}}` кроме двух строк для шага 3.
- Хвост шага (см. выше). В журнале установки: `ГГГГ-ММ-ДД — шаг 1: база «…», <имя>, бизнес: <одна строка>`.

## Шаг 2 — Разделы (10–15 минут)

**Покажи заготовки** одной таблицей (из `_шаблоны/разделы/README.md`: название · что ведём · одна карточка = …) и **порекомендуй 2–3 под описание бизнеса из шага 1** — с одной фразой, почему. Скажи: «Остальные дозаведём потом одной фразой „заведи раздел …“. Лучше начать с двух-трёх и обжить их, чем завести восемь пустых».

**Спроси:** какие разделы заводим сейчас? Нужен раздел, которого нет в списке, — назови его.

**Потом по каждому выбранному разделу — три вопроса** (все разделы в одном сообщении, если их ≤ 3; иначе по одному разделу за сообщение). Вопросы — из заглушек `{{…}}` в `_шаблоны/разделы/<Раздел>/_правила.md`; обычно это: что считаем единицей (кого считаем клиентом / какие встречи), когда обновляем, что ещё важно помнить. Для раздела не из списка — заготовка `_шаблоны/раздел-с-нуля/`: что это за область и единица · 3–5 обязательных полей · какие вопросы будешь задавать.

**Сделай для каждого раздела:**
- `mkdir <Раздел>` → скопируй `_правила.md` и `карточка.md` (как `<Раздел>/_шаблон-карточки.md`) из заготовки → подставь ответы вместо `{{…}}`, даты — сегодняшние. Не оставляй ни одной заглушки: не ответили — убери строку.
- В `ОГЛАВЛЕНИЕ.md` → «Разделы»: `- [[<Раздел>/_правила|<Раздел>]] — <что ведём одной строкой>`.
- Открой каждый созданный файл и перечитай.
- Хвост шага. В журнале установки: `… — шаг 2: разделы <список>`. В `СЕЙЧАС.md` → «Где остановились»: «Шаг 2 сделан: разделы …. Дальше — шаг 3, правила».

## Шаг 3 — Правила и запреты (5 минут)

**Спроси одним сообщением:**
1. Откуда обычно берётся текст созвонов и встреч? (автозапись Zoom/Meet/Телемоста · бот транскрибации, например https://t.me/rutranslaterobot — присылаешь аудио, получаешь текст · диктофон · пока никак — буду пересказывать словами)
2. Откуда берутся документы — договоры, КП, переписка? (почта · мессенджер · папка на диске · CRM)
3. Вот что сюда нельзя класть по умолчанию: паспорта и СНИЛС людей, медицинские документы, домашние адреса и личные телефоны, пароли и ключи, личные банковские данные. Есть что добавить к списку — что-то, чего в базе быть не должно именно у тебя?

**Сделай:**
- В `AGENTS.md` заполни «Откуда берётся сырьё» и «Дополнительно нельзя класть» (нет добавлений → «— (стандартный список)»).
- Если человек назвал источник созвонов — в `_правила.md` разделов «Планёрки»/«Клиенты» (если заведены) в «Когда обновлять» допиши одну строку: «Текст созвона — <откуда>».
- Создай папку `_личное/` с файлом `README.md`: «Эта папка есть только на этом компьютере и в облако не уходит. Сюда — то, что нельзя показывать никому». Проверь, что `_личное/` есть в `.gitignore`.
- `git config user.name` пустой → спроси имя и почту, запиши (`git config user.name/user.email`), объясни: «чтобы в истории было видно, кто что менял».
- Открой `AGENTS.md`, перечитай блок вверху — заглушек `{{…}}` не осталось.
- Хвост шага. В `СЕЙЧАС.md`: «Шаг 3 сделан. Дальше — шаг 4, первое наполнение: понадобится текст последнего созвона или любой рабочий документ».

## Шаг 4 — Первое наполнение (10 минут)

Цель шага — момент «ага»: человек задал вопрос, база ответила цитатой из его же материала.

**Спроси:** есть ли под рукой текст последнего созвона, планёрки, переписки или любой рабочий документ? Вставь сюда или укажи файл. Если нет — есть два запасных пути: (а) продиктуй три мысли или договорённости, которые сейчас в голове, (б) попробуем на примере — в базе лежит вымышленный клиент «ООО Ромашка».

**Есть материал** → выполни умение `sozvon` (созвон) или `zapisi` (документ) целиком: превью → «ок» → сырьё в `Сырьё/Источники/` → карточка/разбор в разделе или `База/` → ссылки → `ОГЛАВЛЕНИЕ.md` → `ЖУРНАЛ.md`. Потом предложи задать вопрос: «Спроси меня что-нибудь про это — например, „что мы обещали <кому>?“» → ответь по правилам «Как искать и отвечать» из `AGENTS.md`, **с цитатой**.

**Три мысли** → умение `mysl` на каждую, потом вопрос «что я просил не забыть?».

**Пример** → «спроси: что мы обещали Ромашке?» → ответь по `_шаблоны/пример-клиента/` по правилам «Как искать и отвечать». Потом объясни, что так же будет с его данными, и запиши в `СЕЙЧАС.md` → «Следующий шаг»: «Кинуть первый свой созвон: „был созвон с …, вот текст“».

**Сделай:** хвост шага. В журнале установки: `… — шаг 4: первое наполнение (<свой созвон / документ / мысли / пример>), первый вопрос: «…»`. Скажи: «Это и есть вся механика: кладёшь — спрашиваешь. Остался последний шаг — облако и две привычки».

## Шаг 5 — Облако и ритуалы (10 минут)

**1. Два ритуала — объясни в четырёх строках:** начало сессии я делаю сам (подтяну облако, скажу, где остановились). Конец — ты говоришь **«заверши сессию»**: я проверю следы, обновлю «Сейчас», запишу в журнал, отправлю в облако. Без этой фразы база не знает, что работа закончилась. Раз в неделю я сам делаю **бэкап** — копию базы и всего, чему ты научил ИИ, чтобы на новом компьютере всё вернулось фразой «восстанови меня». Ты раз в неделю говоришь «итоги недели», раз в месяц — «проверь порядок».

**2. Облако.** Спроси: есть ли аккаунт на GitHub? (да · нет, заведу сейчас на github.com — две минуты · потом)
- **Есть.** Проверь `gh auth status`. Работает → `gh repo create <имя-латиницей> --private --source=. --remote=origin --push` (имя предложи из названия базы, например `second-brain`). Нет `gh` → объясни: на github.com «New repository», имя, **Private**, без галочек «Add README»; попроси прислать ссылку; затем `git remote add origin <ссылка>` и `git push -u origin main`. Просит войти — скажи человеку, что откроется браузер, это нормально.
- **Потом.** Пропусти. В `СЕЙЧАС.md` → «Открытые вопросы»: «Подключить облако: заведи аккаунт на github.com и скажи „подключи облако“». Всё остальное работает и без него.

**3. Проверка.** `python3 _скрипты/proverka.py`. Красное — почини сейчас. Жёлтое — покажи и предложи починить.

**4. Первое «заверши сессию»** — выполни умение `finish` целиком (три следа, `СЕЙЧАС.md`, журнал, коммит, отправка в облако, если подключено).

**4а. Бэкап по расписанию.** Первый бэкап уже сделан на пункте 4: «заверши сессию» делает его сам, когда бэкапа ещё не было (проверь, что в отчёте он есть; нет — выполни умение `backup`). Теперь — регулярная задача раз в неделю:
- У тебя есть инструмент регулярных задач, которые запускаются на этом компьютере (в приложении Claude — «Запланированные задачи» / Scheduled tasks, в Codex — автоматизации) → создай сам: раз в неделю, папка — эта база, текст задачи «сделай бэкап». Скажи человеку: «Поставил бэкап на каждую неделю — <день, время>».
- Нет такого инструмента → скажи: «Если в твоём приложении есть регулярные задачи — заведи одну: раз в неделю, в этой папке, текст „сделай бэкап“. Не заведёшь — не страшно: „заверши сессию“ сам делает бэкап, если его не было неделю».
- Скажи про флешку и двухфакторный вход: это уже есть в отчёте бэкапа — не повторяй, если он это сказал.

**4б. Проверка правил.** Блок вверху `AGENTS.md` заполнен на шагах 1 и 3 — проверь файл по `references/pravila.md` (длина, заглушки, временное, повторы). Покажи таблицу ✓/✗ одной строкой на пункт; ✗ — почини после «ок».

**4в. Пробный запуск.** Проверь сам, что всё заведётся без тебя: ты Claude Code → `CLAUDE.md` содержит `@AGENTS.md`, а `.claude/skills` открывается и в нём 8 умений; `python3 _скрипты/proverka.py` — 0 красных; бэкап был (в `_настройки-ИИ/` есть `ОПИСЬ.md`). Не сходится → почини. Потом попроси человека: «Закрой меня и открой снова в этой папке. Напиши „где мы остановились?“. Я должен начать со строки „Задача: …“, второй строкой — „Где остановились: …“, и ответить по файлу „Сейчас“. Иначе скажи „прочитай AGENTS.md“ — значит, правила не подхватились». Это проверка, что память работает между разговорами: внутри одного разговора её не видно.

**5. Завершение.** В `УСТАНОВКА.md`: все ✅, `status: завершена`, `step: 5`, строка в журнале установки «установка завершена». В `ЖУРНАЛ.md` → хронология: `## [ГГГГ-ММ-ДД ЧЧ:ММ] установка | завершена: разделы …, облако <да/потом>`. Коммит «Установка завершена».

**Скажи:** «Установка завершена. Дальше просто работай — три фразы, которые нужны каждый день: „был созвон с …, вот текст“ · „что у нас с …?“ · „заверши сессию“. Остальное я подскажу сам. Пример „ООО Ромашка“ можно удалить, когда появится первый свой клиент, — скажи „удали пример Ромашки“. Если компьютер сломается — на новом поставь агента и скажи „восстанови меня“.» Напомни, где искать ответы: «спроси меня „как пользоваться?“ или „почему так?“ — отвечу по методологии».

## Чего не делать

- Не делать два шага в одном разговоре без явной просьбы. Не начинать шаг сам — только по слову человека.
- Не выдумывать содержимое: ни клиентов, ни задач, ни «типичные для вашей ниши» разделы без подтверждения.
- Не трогать `_шаблоны/` (кроме чтения) и не удалять пример без просьбы.
- Не пропускать хвост шага: без отметки в `УСТАНОВКА.md` следующая сессия не узнает, где вы.
- Не отправлять в облако, пока не пройдена проверка на запрещённое (умение `finish`, шаг 2).
- Не создавать регулярную задачу в облаке (облачные задачи не видят папок этого компьютера) — только ту, что запускается здесь.
